# M1 acceptance: the evidence and the sign-off

Milestone 1, "A Sprite Lives", is done when the nine criteria of design §7.4 hold ([design v38](../design/m1-a-sprite-lives-v38.md#74-m1-acceptance-criteria)). This page gathers what shows each one, and holds the playability checklist (A8) that the owner plays through in Windows Terminal. It was written by slice 19 ([#20](https://github.com/Keazra/terra-sprites/issues/20)), against `main` at `3d8178f` and the slice's own fixes. The replay docs (PR #123), which merged after the measurements, change no code.

## What the check found

Every rule in design §3–§6 was traced to the code that does it and the test that covers it. The code fell short of the spec in three places, each fixed with a test that failed first:

- **A blocked sprite gave up too soon.** When a sprite stood on the tile in front of a bush, another sprite walking to the bush searched only for a way to that one tile, found none, and gave up, even when another side of the bush was free the long way round (§3.7).
- **A shove into a thornbush showed no hurt.** The red `!` started only when an action ended, and a sliding sprite has none (§6.3).
- **Loading forgot the themes folder.** After `F9` or `Ctrl+O`, the Themes menu listed only the two built-in themes (§6.7).

In seven places the code was right and the spec's words weren't, or left a case open; design v38 says what the code does. Smaller findings that don't stop M1 are follow-up issues: [#124](https://github.com/Keazra/terra-sprites/issues/124) (`?` and capitals in kitty-protocol terminals, not Windows Terminal), [#125](https://github.com/Keazra/terra-sprites/issues/125) (resting never counts as relief from tiredness, a tuning gap) and [#126](https://github.com/Keazra/terra-sprites/issues/126) (rules with no test yet).

## A8: the playability checklist

Play the build in Windows Terminal, at least 100×30 (140×40 is better), and tick each line that behaves as it says. Anything that doesn't is a comment on [#20](https://github.com/Keazra/terra-sprites/issues/20), or a new issue.

### The world and the sprites (design §3–§5)

Watch a while at 8× or 16×; these happen on their own.

- [x] Berry bushes grow from seedlings, drop berries and in time die; a berry left lying rots away, or takes root as a new bush. Thornbushes spread to the tiles near them.
- [x] A ball kicked by a sprite rolls, bounces off what it meets, knocks other balls on and crushes berries in its way.
- [x] Hungry sprites go to bushes and eat, thirsty ones drink at water, tired ones rest, bored ones play, lonely ones go over to others. The Body tab's bars rise and fall with it, and the Chem tab's levels move.
- [x] A sprite that touches a thornbush is hurt (`!`), backs away, and in time learns thornbushes are bad ("learned: thornbushes are bad" in the event log).
- [x] A hit sprite usually backs away from its attacker, sometimes hits back; a cornered one fights.
- [x] Sprites find their way round each other, and pass head-on in narrow places.
- [x] A sprite that dies of hunger, thirst, old age or thorns is counted by cause in the World tab.
- [x] Train a sprite: pet it each time it plays with a ball for a few minutes at 1×, and it plays with balls more; shock it each time it hits, and it hits less.
- [x] `cargo run --release -- --preset <file>` with an edited copy of `data/presets/default.ron` (say, fewer sprites) makes a world to match, and `--data <folder>` with an edited copy of `data/objects.ron` in it changes what things do.

### Starting, the screen and time

- [x] `cargo run --release -- --seed 7` opens on a terrarium with the top bar (tick, speed, seed, sprites, save status, `? help`), the map, the inspector on its World tab, the event log and the status line.
- [x] Making the window smaller than 100×30 shows "Terminal too small" and "needs 100x30, this is …"; the game keeps running, and making it bigger brings everything back.
- [x] `space` pauses and resumes, and holding it doesn't flicker. `.` while paused steps, and holding it keeps stepping. `+` and `-` go from ⅛× up to 16× and Max, and the top bar says the speed; holding `+` stops at 1× and 16×.
- [x] `W` `A` `S` `D` and the arrows scroll the map, Shift by 5 tiles, and it stops at the wall, drawn as a double border.
- [x] `?` opens the help: every key, the colour legend, the emotes and the game's folder. `Esc` or `?` closes it.

### Watching sprites

- [x] Clicking a sprite selects it, and the inspector moves from the World tab to Body: what it's doing, its drives as bars, energy, hydration and injury.
- [x] `[` and `]` go through Body, Brain, Chem, Genome and World. Brain says what it's paying attention to and why, and its memory below. `PgUp` and `PgDn`, or the wheel over the inspector, scroll a long tab.
- [x] The map flashes an `X` where the selected sprite is heading and shades what it's paying attention to in grey; `v` shows exactly what it's doing.
- [x] `T` tracks the selected sprite, keeping it in the middle of the view; scrolling by hand stops it.
- [x] `Tab` and `Shift+Tab` select the next and previous sprite. `l` opens the sprite list: the arrows choose, `Tab` changes the order, `Enter` goes to the sprite.
- [x] `b` switches sprite colours between the strongest drive and plain, and the status line says which.
- [x] The event log shows play, hits, hurts, lessons and deaths, newest first; `m` switches between all events, the selected sprite's and the major ones.
- [x] The emotes show over sprites: a red `!` when one is hurt, a yellow `‼` when zapped or shocked, `?` when one gives up, `z` while resting, and a heart when it feels something good, such as a pet.
- [x] When the selected sprite dies, the inspector says so.

### The Cursor

- [x] The status line always names what's under the Cursor, and the mode.
- [x] `Z`, `X` and `C` switch Select, Train and Grab; the mouse wheel over the map does too, and `Esc` goes back to Select.
- [x] Train mode: a click pets the sprite under the Cursor and a right click zaps it; `Ctrl` with a click, or Shift with `Q` or `E`, makes it a hug or a shock. A mark flashes by the Cursor for each.
- [x] `Q` and `E` click left and right where the Cursor is, once per press, in every mode.
- [x] `F`, or the middle button, makes the Cursor follow the sprite under it, with solid arrows; again to stop.
- [x] `H` makes the Cursor visible to sprites in the current mode (a frame of light, and "seen" on the status line), and hides it again. Each mode keeps its own: shown in Train, it's still hidden in Grab.
- [x] Grab mode: a click picks up a berry or a ball and a click elsewhere puts it down; a click on a sprite leads it on a leash, and another click lets go.
- [x] Holding the right button (or `E`) in Grab mode aims a throw of a held item, or a shove of a led sprite, with a line; letting go sends it, and `Esc` cancels the aim.
- [x] A sprite shoved into a thornbush shows the red `!`. (Fixed in this slice.)
- [x] `C` again in Grab mode opens the Place menu: berry bush seedling, berry, ball, new sprite, sprite from a genome file. The next click places it; a right click puts it away.

### Sprites of your own

- [x] `r` names the selected sprite: type a name, `Tab` for a random one, `Enter`. The name shows in the inspector and the event log.
- [x] `g` saves its genome, and the status line says where; the Place menu's "sprite from a genome file" lists it and places a copy.

### Themes

- [x] `Ctrl+T` lists cp437 and ascii, then any `.ron` file in the `themes` folder of the game's folder. Picking one redraws the map at once.
- [x] After loading a save (`F9`), `Ctrl+T` still lists your own themes. (Fixed in this slice.)
- [x] `--ascii` draws the map in plain ASCII, and `--theme <file>` starts in a theme of your own.

### Saves

- [x] `F5` saves, and the top bar says "saved just now". `F9` loads it back, asking first if the world has run since; a loaded world starts paused, with the view where it was.
- [x] `Ctrl+S` saves under a name you type; `Ctrl+O` lists every save, newest first, to load one.
- [x] Quitting writes an autosave, unless the world hasn't run since it was last saved. Saves are in `saves` in the game's folder (`$env:APPDATA\terra-sprites\saves` in PowerShell).
- [x] Left running, unpaused, for 10 minutes, the world autosaves ("Autosaved"); paused time doesn't count.
- [x] `F9` with no quicksave yet says "There's no quicksave yet: F5 makes one".

### Replays

- [x] After quitting, `cargo run --release -- --replay "$env:APPDATA\terra-sprites\last_session.replay"` plays the session back, paused at first, saying where it starts and ends.
- [x] During playback, Train and Grab are refused with "It's a replay: …", while time, the view and the inspector work. It pauses at the end, saying so.
- [x] `Ctrl+R` takes it over: "You took over the replay at tick …: it's your world now", and clicks work again.

### Quitting and the forced panic

- [x] `Esc` from Select asks "Quit? (y/n)"; only `y` quits, and the terminal is as it was before.
- [x] `Ctrl+C` quits at once, and the terminal is as it was before.
- [x] `cargo run --release -- --force-panic` crashes on purpose. Afterwards the terminal is usable: what you type shows, the mouse selects text again, and the prompt is back.
- [x] After the forced panic, `last_session.replay` is in the game's folder and plays with `--replay`.

### Speed (A5)

- [x] `cargo run --release -p terra-sim --example speed` reports 200 ticks a second or more.
